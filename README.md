# Secret Book

Secret Book 帮你通过 Claude Code、Codex 或 WorkBuddy 管理和取用飞书多维表格中的凭证。你可以维护令牌表、登记 API Key 和账号配置，也可以选取已有凭证，确认后保存到业务 Skill／Plugin 的本机配置，或仅供一次命令使用。

2.5.4 在安装完成后先介绍四个角色各自的用法，再让你选择本次角色；随后按所选角色准备必要的登录、表连接或本地接入开发。

## 使用前需要知道

- **凭证以明文保存在飞书表和业务本机配置中，不加密。Secret Book 不是密码管理器。** 飞书平台方和拥有相应表格权限的人可以查看数据。
- 飞书多维表格保留 180 天历史记录，删除后另有 30 天回收站。只建议保存可随时轮换的中低价值凭证；高价值凭证应使用 1Password 等专业密码管理器。
- 个人使用时，建议把表权限收紧到仅本人；共享使用时，由管理员管理实际访问权限。选择本文中的角色不会获得额外飞书权限。
- 尽量在自己的飞书表或本机文件中填写密钥。在对话中粘贴凭证，或让 Agent 在浏览器中填写凭证，会使值进入会话记录。
- Secret Book 自身只显示记录信息、键名和掩码。临时命令可能自行打印环境变量，Secret Book 不过滤目标程序的输出；复制到剪贴板后也不会自动清空。

## 先确定本次角色

角色表示“这次要做什么”。同一个人可以兼任多个角色，例如先建表，再录入凭证，最后为自己的工具配置凭证。

| 角色 | 适合的任务 | 需要准备什么 |
| --- | --- | --- |
| **令牌表管理员** | 创建或接管表、维护表结构、安排协作者权限 | 用于管理表的飞书账号；接管时提供已有表链接 |
| **凭证提供者／维护者** | 登记和修改凭证、维护账号与用途、设置可见人员 | 已有表链接及编辑权限；需要维护的记录 |
| **凭证使用者** | 给业务工具配置凭证、临时执行命令、复制单个值 | 已有表链接及读取权限；具体使用目标 |
| **业务 Skill／Plugin 接入开发者** | 让自己的工具支持 Secret Book 配置保存与修复 | 待接入产物的代码和配置说明；本地设计与模拟测试无需真实凭证 |

日常使用时，你可以直接点名角色，也可以请 Agent 根据明确任务先说明判断；拿不准时再让你选择。例如，“给这个 Plugin 配好 Key”属于凭证使用者，“为我开发的 Plugin 实现凭证接入”属于接入开发者。

```text
请用 secret-book 处理这个任务：〈你的任务〉。先说明本次按哪类角色处理；信息不足时让我选择。本机没有配置时，请按该角色的首次使用说明引导我。
```

同一任务继续时可以沿用角色；工作内容变化时重新说明。角色确认与飞书身份确认、具体写入确认分别处理。本机缺配置不表示应当新建表，也不表示使用者应转为管理员。

## 让 Agent 帮你安装

把下面一段发给你正在使用的 Claude Code、Codex 或 WorkBuddy：

```text
请安装 secret-book：优先用 https://github.com/cookaihq/secret-book，网络故障时改用 https://cnb.cool/zhidateam/tannt/secret-book.git。保留已有配置，检查当前 Agent 能否发现和调用；缺少 Lark CLI 时自动安装并检查可用。安装完成后，先说明四个角色各自怎么使用，再让我选择本次角色。
```

脚本支持 macOS、Linux 和原生 Windows（2.4.0 起）。原生 Windows 使用 PowerShell，无需 WSL。Agent 执行脚本需要 [uv](https://docs.astral.sh/uv/) >= 0.8；访问令牌表还需要 `lark-cli`、本人完成登录的飞书账号，以及飞书网络。安装或补齐依赖、准备访问飞书时，Agent 会联网从官方来源自动安装缺少的 Lark CLI，保留已有设置，检查可用后继续；无需安装宿主连接器。登录仍由你本人完成，安装成功不代表已经登录。下载或本机权限阻止安装时，Agent 会说明具体原因。

Windows 写入配置需要支持文件访问权限的磁盘，例如 NTFS。安装和调用须在同一实际运行环境中进行；Windows 原生与 WSL 的依赖、登录和个人配置各自独立。只在飞书界面维护记录，或只讨论业务接入方案时，不必先建立本机令牌配置。

安装完成时，Agent 会先在回复正文介绍四个角色分别能做什么、怎样开始，再让你选择“令牌表管理员／凭证提供者或维护者／凭证使用者／业务 Skill 或 Plugin 接入开发者”。已有表或账号也会展示这份引导。你选择后才进入相应流程；暂不选择可以停在安装完成。角色表示这次的任务，之后可以切换。

## 第一次使用：按角色准备

一套“令牌配置”记录要访问哪张表、通过哪个飞书登录配置访问，以及确认过的实际用户身份。飞书登录配置也称 **profile**，用于区分本机不同账号或应用。

令牌表保存在飞书，与创建时使用哪种电脑系统无关。换电脑或重装后，可以用表链接和有权限的本人账号只读连接已有表，再确认保存本机连接；各运行环境的依赖、登录和配置分别检查。仅为继续使用已有表，无需接管或补齐表结构。

新建 profile 时，未指定名称就默认使用 **`secret-book-feishu`**；你也可以直接指定其他名称。设置成功后，Agent 会告诉你实际名称，并提醒这个名字可以修改。已有 profile 保留原名；默认名被其他账号或应用占用时，会请你另选名称。

首次配置前，可先让 Agent 检查本机已有设置：全局文件为空，不代表当前项目没有连接；已有配置损坏或身份改变时，应修复原来源。下面的流程以确实没有可用连接为前提。

需要登录时，Agent 会先在回复正文说明当前状态和可用账号，再让你选择：

- 没有已登录账号：**登录飞书账号（推荐）**、暂不登录。
- 已有可用账号：**使用当前账号：姓名（推荐）**、登录其他账号、暂不继续。有多个候选且尚未选定时，先让你选择具体账号。

选择登录后，Agent 会完成必要的应用准备，再展示授权链接或二维码，由你本人登录。
如果需要绑定应用，会先说明应用、目标环境、是否替换已有绑定，以及允许以你的用户身份访问资源，由你确认。
登录其他账号会保留原账号；登录完成后还会展示并核对实际身份。已有令牌配置更换账号时，另经确认改绑，不会因浏览器登录了另一账号就自动切换。选择暂不登录会保留进度，等你准备好后继续。

```text
请用 secret-book 登录另一个飞书账号，保留已有账号和令牌配置。展示授权链接或二维码，登录完成后让我确认实际身份，再决定是否用于当前令牌表。
```

### 令牌表管理员：准备一张可供使用的表

新建会在所选飞书账号下创建表，并在确认后保存本机连接。把配置名替换为便于识别的名称，例如“工作”或“个人”：

```text
请用 secret-book 按令牌表管理员处理：检查已有配置和可用飞书账号，让我选择并确认身份后，新建令牌表。本机配置命名为〈配置名〉，保存前告诉我位置。
```

需要管理已有表结构时，从飞书复制该表链接，再提出接管请求。Agent 先只读检查并展示差异，再按你的授权补齐。**接管会补建缺失字段；字段类型不符合要求时停止，不修改表结构。**

```text
请用 secret-book 按令牌表管理员接管这张表：〈飞书表链接〉。确认我的飞书身份后，检查字段并补齐缺项；类型不符时停止。本机配置命名为〈配置名〉，保存前告诉我位置。
```

首次使用顺序为：选择账号并登录 → 确认实际身份 → 创建或检查表 → 确认保存本机连接。Agent 会展示登录配置、应用、用户名和用户标识。第一套本机连接自动成为当前配置，后续新增保留原当前项。

预期结果是表链接、配置名称、实际保存位置和已经核实的连接结果。新表没有凭证记录是正常状态。创建表不代表协作者权限已设置；需要共享时，在飞书权限入口确认成员范围，再把表链接交给成员，由他们使用各自账号连接。

### 凭证提供者／维护者：维护已有表中的记录

如果你直接在飞书界面填写或修改记录，**本机 Secret Book 没有初始化也可以继续**。先向管理员取得表链接和编辑权限，再维护指定记录。

一条记录可以保存一个 Token，也可以保存一组配套字段，例如数据库地址、用户名和密码。名称、服务、账号和用途帮助使用者找到正确记录；密钥值填入表内，允许取用的人员在 `visible_to` 列维护。

```text
我负责维护这张令牌表：〈飞书表链接〉。请用 secret-book 的记录格式指导我填写〈凭证用途〉，说明需要维护哪些字段和可见人员。我会在飞书界面填入密钥，不把值发到聊天里。
```

需要 Agent 代为新增记录时，先使用本人账号连接已有表，再明确记录信息和输入来源。当前脚本支持新增和经确认补齐缺失的记录 ID；已有记录内容的修改、删除及可见人员名单在飞书界面维护。

**当前新增脚本不能同时设置可见人员，新增记录的名单为空。** 需要限定人员时，应在飞书界面按既定权限完成录入，不能把“先无限制保存、再补名单”当作已实现的受限写入。

没有表链接或编辑权限时，先由管理员准备；确实要自己建表时再转入管理员任务。预期结果是记录名称、账号、用途和变更范围；仅提供填写指导不代表已经修改记录。密钥在原服务轮换后，表和各使用者本机配置需要分别更新。

### 凭证使用者：从已有表取用

先向管理员取得表链接，并使用自己的飞书账号连接。没有表链接时，可以取得已有表，或改为自行填写业务工具的本机配置；只有你明确决定建立个人表时才进入建表流程。

首次接入已有表会检查字段及本人可见的记录，不补列、不补记录 ID。缺列时交给管理员，缺 ID 时交给维护者；空表或没有可见记录都不会触发新建另一张表。**2.4.0 用户需留意：旧接管会补列，旧查询可能补写 ID；该版本不能替代新版只读连接。**

```text
请用 secret-book 按凭证使用者处理：我要从这张已有表〈飞书表链接〉为〈Skill／Plugin〉配置凭证。先检查本机连接和实际配置来源，用我的账号只读连接已有表。让我确认记录、字段对应关系和保存位置，隐藏密钥值。
```

已有可用连接、表和记录满足当前版本要求后，预期流程是：核对身份 → 列出候选 → 确认记录、账号及字段 → 确认目标文件 → 保存并检查业务工具实际读取结果。保存成功和服务鉴权成功会分别说明。

没有可用记录时，由维护者补齐；权限不足时由管理员处理。记录不存在与对你不可见无法区分时，Agent 应如实说明。缺连接、缺记录或权限不足都不需要另建一张表。

业务配置已经可用时，正常运行业务工具即可。仅本轮使用或明确不保存时，可以临时执行命令或复制单个值，见下方常用请求。

### 业务 Skill／Plugin 接入开发者：先完成本地接入

**接入设计和模拟测试无需先初始化 Secret Book 的真实令牌配置。** 提供待接入代码或配置说明，让 Agent 从业务工具实际需要的字段和读取方式开始。

```text
请按业务 Skill／Plugin 接入开发者处理，为〈产物名称或路径〉设计 Secret Book 接入。先核对真实配置字段和读取来源，准备配置声明、无值来源报告及验证入口；使用模拟记录和临时目录测试，不访问真实令牌表。
```

预期结果是与业务工具一致的接入方案及本地验证结果。业务工具负责说明需要什么、从哪里读取以及怎样验证；Secret Book 负责记录选择、确认和写入。开发细节见随包的 [业务配置流程](references/consumer-setup.md)。

需要真实联调时，再明确测试表和操作范围，按凭证使用者流程连接；需要建测试表或录入测试记录时，分别确定管理员或维护者职责。模拟测试通过不代表真实飞书登录或服务鉴权通过。

## 常用请求

以下请求用于已有可用连接、表结构和记录均已准备好的场景。临时命令会实际执行，复制会把值写入系统剪贴板；请给出明确用途。

| 对 Agent 说什么 | 会得到什么 |
| --- | --- |
| “用 secret-book 列出 GitHub 相关凭证，不显示值。” | 名称、服务、账号、用途和到期时间；多条候选由你选择 |
| “用 secret-book 为〈Skill／Plugin〉配置或修复凭证，先让我确认来源和保存位置。” | 确认字段映射后写入业务工具配置，并报告实际来源 |
| “这次用〈记录名〉执行〈明确命令〉，只在本次命令中使用。” | 凭证临时加入子进程环境，不另存为业务配置文件 |
| “用〈记录名〉执行〈明确命令〉；成功后记住这次选择。” | 成功后保存这张表、当前项目与命令之间的绑定，供后续临时取用 |
| “把〈记录名〉里的 PASSWORD 复制到剪贴板。” | 单个值进入剪贴板，回复只显示键名和掩码 |
| “查看当前令牌配置，再把默认设置切换到工作。” | 切换本机默认使用的令牌配置，并回读确认 |

临时命令绑定只记选择，不保存密钥值。切换到另一张表后不会复用原表的绑定；可以说“列出 Secret Book 自动绑定”或“解除当前项目中〈命令名〉的绑定”。

## 为业务工具保存和修复配置

这是凭证使用者最常见的长期使用方式。Agent 先检查业务工具需要哪些字段、实际从哪里读取，再让你确认记录、服务账号、**表中字段 → 业务字段**以及准确的目标文件；唯一候选首次也会确认。值由脚本直接写入文件，不需要你在聊天中粘贴。

首次新增沿用你已选定的位置；没有既定位置时，建议保存到个人全局，确认后再写入：

| 目标 | 首次全局保存位置 |
| --- | --- |
| Plugin | `~/.config/〈Plugin名〉/.env` |
| 独立 Skill | `~/.config/〈Skill名〉/.env` |
| 明确选择仅当前项目 | 当前工作文件夹的 `.env.local` |

这里的 `~` 是实际运行环境的个人文件夹，位置见下一节。业务工具必须实际支持读取目标文件；独立 Skill 如需显式启用全局配置，仍按自己的规则启用。项目内保存前还会检查目标未被 Git 跟踪且已被忽略。

修复已有错误时，写回实际生效的原文件、原字段和原作用范围，保留其他内容。来自环境变量的错误先查明启动或注入来源，不另写一份文件掩盖问题。需要改变保存位置时，可让 Agent 检查覆盖关系后确认迁移。

**保存后直接使用业务 Skill／Plugin。** 它读取自己的本机配置，日常运行无需访问 Secret Book。表中轮换、名单变化或默认令牌配置切换，不会自动更新或收回已保存的值；需要更新时重新检查并确认，保留你手动修改过的配置。

Agent 会分别报告文件写入、本机读取和线上鉴权结果。网络故障、余额、权限或限流不直接等于密钥错误；修复配置也不自动重发原业务请求。尚未提供配置声明和来源检查的旧工具，需先核对真实配置方式。

## 配置保存在哪里

Secret Book 自身的表定位和飞书身份保存在个人目录的 `.config/secret-book/.env`，与业务工具的密钥配置分开。业务配置确认、临时命令绑定和本次任务的进度也在这个目录，只保存记录信息、选择和校验值，不保存密钥值或飞书授权码。任务关闭后，不会成为下次调用的默认角色。

| 运行环境 | Secret Book 个人配置文件 |
| --- | --- |
| macOS | 通常为 `/Users/〈用户名〉/.config/secret-book/.env` |
| Linux | 通常为 `/home/〈用户名〉/.config/secret-book/.env` |
| Windows 原生 | 通常为 `C:\Users\〈用户名〉\.config\secret-book\.env`，即 `%USERPROFILE%\.config\secret-book\.env`；不是 `%APPDATA%` |
| WSL | WSL 自己的 Linux 用户目录，例如 `/home/〈WSL用户名〉/.config/secret-book/.env`；不自动共用 Windows 目录，完整流程尚未验证 |

Agent 应报告实际完整路径。配置独立于 Skill 安装目录，更新 Skill 不应删除它们。macOS/Linux 写入文件仅允许本人访问；Windows 写入前设置并核对仅当前用户与系统账户可访问的权限，磁盘不支持时停止。已有业务项目目录的权限不改动，文件权限不提供加密。

### 哪一套令牌配置会生效

“工作”和“个人”等名称表示不同的表连接，与四类角色无关。可以保存多套连接，但任何时刻只有一套当前配置，它也是默认配置。切换不会删除其他配置，也不会切换 `lark-cli` 的全局登录配置。

按默认方式查表时，Secret Book 从以下来源选择第一套完整配置：

1. 运行程序时的环境变量。
2. 当前工作文件夹的 `.env.secret-book`。
3. 当前工作文件夹的 `.env.local`。
4. 当前工作文件夹的 `.env`。
5. 显式启用后，个人全局文件中的当前配置。

工作文件夹是 Agent 执行任务时所在的目录，与 Skill 安装目录不同；不会向父目录搜索。表定位、登录配置和身份字段须在同一层完整提供，部分缺项需要修复，不能从不同层拼接。

可以说“这次明确使用 Secret Book 的个人全局配置”；Agent 会为查表操作加上 `--use-global-config`，它仍受前面的完整项目或环境配置覆盖。也可以说“这次明确使用名为工作的一整套令牌配置”；Agent 用 `--config-name` 直接选取该命名配置，不与项目或环境拼接，也不改变默认项。

查看、切换全局命名配置与查表是不同操作：能列出本机“工作”配置，不代表后续查表已启用它。排查时可直接说：

```text
请检查 secret-book 本次实际使用的工作文件夹、令牌配置名称、飞书身份和配置来源；说明是否有覆盖，隐藏所有密钥值，保留已有配置。
```

## 共享表中谁能取用

飞书权限决定谁能访问和修改表。表中的 `visible_to` 人员名单进一步限制通过 Secret Book 取用的记录：空值表示不额外限制，非空时只有名单内用户能通过 Skill 取用。管理员也没有绕过名单的入口。

名单在飞书界面维护，不会自动授予飞书权限，也不能阻止拥有相应表格权限的人直接查看表中明文。撤回名单或删除记录不等于吊销凭证；需要让旧凭证失效时，应在对应服务中完成吊销或轮换。

## 检查 Agent 的使用规则

通过脚本取用或保存配置前，Agent 会检查当前宿主的相关规则，报告缺失、旧规则、项目覆盖或无法确认的状态；检查不自动安装或修改全局规则。

安装或更新规则时，你会先在回复正文中看到目标文件、作用范围、新增或替换方式，以及代码块中的完整规则原文；下面才出现确认选项。第一项是“安装规则块（推荐）”或“更新规则块（推荐）”，第二项是“暂不安装”或“暂不更新”，由你看完后确认是否写入。

```text
请检查当前 Agent 的 secret-book 使用规则。先在回复正文中展示目标文件、作用范围、新增或替换方式，以及完整规则代码块，再让我选择是否安装或更新；保留其他规则和共用文件的链接。
```

规则文件只保存使用说明，不保存业务密钥。找到文件不代表当前会话已经加载，修改后仍需核对宿主实际入口。除三种主要宿主外，还有其他 Agent 的规则检查入口，范围见 [Agent 规则检查](references/agent-rules.md)；规则检查支持不等于该宿主已完成完整业务验收。

## 遇到问题时，可以这样问

| 遇到的情况 | 可以发给 Agent 的请求 |
| --- | --- |
| 刚安装，提示没有配置 | “先确认我的本次角色，再检查所有适用配置来源。缺本机连接时按角色引导，不要直接建表。” |
| 换电脑或重装后继续使用已有表 | “请用 secret-book 连接这张已有表〈飞书表链接〉。检查当前环境和配置，用我的账号只读连接，保存本机连接前告诉我位置。” |
| 提示账号未登录或身份变化 | “请核对这套配置原来绑定的身份，展示需要使用的账号，再引导我登录或确认改绑。” |
| 在 WorkBuddy 等工具中却提示 Hermes 上下文未绑定 | “请先核对当前工具与飞书命令行实际选择的配置来源，说明冲突原因，保留已有账号，不要直接让我配置 Hermes 或重复登录。” |
| 想使用另一个飞书账号 | “请提供登录其他账号的入口，保留已有账号，登录后让我确认身份和是否改绑当前令牌配置。” |
| 已在网页授权，任务仍未继续 | “我已完成刚才的授权，请继续同一次登录并检查本机状态，不要直接生成新的授权请求。” |
| 写入后报网络错误，结果不明 | “请先核对刚才的表、记录或文件是否已经写入，告诉我能确认的结果，再决定下一步。” |
| 旧安装读不懂已有配置 | “检查当前 Agent 实际加载的路径和版本，保留全部已有配置，更新到兼容版本后再验证。” |
| Windows 找不到依赖或仍提示不支持 | “确认当前是 Windows 原生还是 WSL，核对实际 Skill 路径、版本、依赖和个人配置目录，保留已有配置。” |
| 查询结果为空或记录找不到 | “核对当前表、本人身份和可见范围；无法区分不存在与不可见时如实说明，不创建新表。” |

登录时，Agent 会展示原始授权链接、二维码及目标账号；完成网页操作后，你回到对话回复“已授权”，Agent 再核对本机登录。网页成功不等于本机登录已经完成。原授权请求失效或上下文丢失时，Agent 应说明原因，取得新的授权请求确认后再继续。

同一未完成任务可以恢复角色、目标和待确认进度；重新继续时仍要核对输入是否变化，不能把已有确认记录当作本次自动授权。换了宿主、工作文件夹或安装，需要重新核对任务。写入结果不明时先回读；取消任务不会删除已经创建的表或撤回已写文件。需要进一步排查时，Agent 可参考随包的 [角色规范](references/roles.md)、[业务配置流程](references/consumer-setup.md) 和 [CLI 说明](references/cli.md)。

## 自动检查更新

自动检查更新默认开启，发现新版时提醒，实际更新需要你确认。可以说“请检查 Secret Book 是否有更新”。检查失败不影响继续使用当前版本，也不代表已经是最新版。

Git 安装在 Windows 使用随包 PowerShell 检查，在 macOS/Linux/WSL 使用 Bash；复制安装按随包更新信息核对稳定版本及目标。三宿主均需核对实际安装形态；WorkBuddy 没有已核实的专用更新 API，无法确认更新能力时会说明限制并继续当前任务。

可以说“关闭 Secret Book 的自动检查更新”；开关只保存并读取个人配置目录 `.env` 中的 `AUTO_UPDATE_CHECK=0`，不走业务配置的覆盖顺序。说“重新开启”即可恢复检查。
