# 为 Skill / Plugin 保存和修复凭证

业务方负责定义配置项、读取本机配置、报告实际来源及解释服务错误。secret-book 负责自身安装/版本、飞书身份与表的准备、记录选择、实际 key 核对，以及确认后写入目标配置文件。正常业务运行直接读取本机配置，不经过 secret-book 启动，也不逐次访问飞书。

## 开始前：检查当前 Agent 与调用者

先完成[明确配置需求](roles.md#明确配置需求)，取得用户指定或确认的实际使用对象，再进入本流程。
“AI Hub”等服务名称加表链接不表示选择了某个同名插件；没有具体 Skill 调用方，也不表示用户已选择 Plugin 共享配置。
对象待定时先按共用入口提问并等待，不先读取候选产物声明、运行加载器或建立 consumer 任务。
对象已明确时沿用，再完成 [角色入口](roles.md#确定角色)：为业务工具取值按凭证使用者；开发接入代码按接入开发者。
本流程不会因为缺少本机连接而要求使用者建表。

1. 从实际调用上下文确认当前 Agent，不按哪个目录存在推测。先运行 `agent-rule --agent <agent>` 做只读检查。可用值和宿主限制见 [Agent 规则检查](agent-rules.md)。自定义配置目录传 `--config-dir`；OpenClaw 使用实际 `--workspace` 或已确认的 `--agent-id`。未知宿主由 Agent 核对其实际加载说明，不冒用其他宿主名称。
2. 报告已有说明是否为旧规则、手写规则待审、存在覆盖/冲突或只在当前项目生效。`managed_current_static` 只说明文件中存在当前受管理块；不证明当前会话加载。文件缺失不自动创建，旧规则不自动覆盖。准备安装或更新时，先按 [修改规则](agent-rules.md#修改规则)在回复正文展示目标、范围、变更方式和完整规则代码块，再提供确认选项；按用户对该预览已有的明确授权或新确认执行。多路径指向同一实体只改一次，保持 symlink。业务密钥永不写进 Agent 规则文件。
3. 从业务产物读取 `references/credentials.json` 或其真实声明。用调用者自己的配置检查入口，在实际工作目录和相同启动环境生成 `secret-book.config-inspection/v1` 报告。报告应包含读取层、每字段来源和缺项/格式问题，**不含值**。不知道配置如何读取时，先查代码或说明，不能靠目录名称猜测。
4. 区分首次新增与修复现有设置。业务方应说明错误依据：缺项/格式检查、鉴权拒绝、或其他明确证据。401 表示服务拒绝当前认证组合，仍需核对 Key、服务地址和账号；网络异常、402 余额、403 权限、429 限流不能直接判定 Key 填错。配置修复不授权自动重发业务请求。
5. 用户选择修改本机文件时，交回业务方指导本机填写，不访问飞书。选择 secret-book 后才查询记录；已明确的管理方式和保存位置继续沿用。仅本轮、短期令牌、明确不落盘或目标不支持保存时，见下文临时取用。

## 首次使用 Secret Book 的分支

- 未安装或版本不认识 `configure`：说明需要 2.3.0 或更新版本，按可用来源安装/更新；不可用时让用户选择自行填写文件。不得拿旧 `run --auto` 替代配置修复。
- 缺少 Lark CLI：按 [依赖自动准备](../SKILL.md#lark-cli-依赖自动准备)直接安装并复检，成功后继续本人身份与已有表连接流程。
- CLI 可用但未登录、身份失效或要登录其他账号：按 [飞书账号选择与登录](../SKILL.md#飞书账号选择与登录)展示实际账号和登录选项；确认身份后再连接表，已有配置换账号须确认改绑。
- 尚无令牌配置：先检查实际工作目录和所有适用来源；全局配置列表为空不足以认定未初始化。确实缺连接时按 [凭证使用者](roles.md#凭证使用者) 连接管理员提供的已有表，以本人身份只读检查。无链接时取得已有表或返回手填分支，不自行建表、接管补列或更换身份。
- 已有配置：核对用户明确提供或已选定的表，再沿用对应来源；完整项目／环境配置直接 `list`。全局当前项用 `list --use-global-config`，明确另一套用 `list --config-name <名称>`。后续 `get/configure` 使用相同选择，不为配置一个 Plugin 改全局默认项。指定表无可见记录时说明结果，用户选择另一张表后才切换，不查其他表来猜测用户意图。损坏、部分缺项、旧格式或身份变化修复原来源。
- 候选多条：列名称、服务和账号供选择。唯一候选也核对 key 并首次确认。缺列交管理员、缺记录 ID 或必填 key 交维护者；记录缺失与不可见无法区分时照实说明，或改为自己填写业务文件。不要求把 Secret 发到聊天，不用临时脚本读取 secret 列。

## 写到哪个文件

| 情况 | 目标 |
| --- | --- |
| 修复文件中已有的有效来源 | 原文件、原字段、原作用域；`--scope` 不把修复改成迁移 |
| 字段来自进程环境变量 | 停止文件写入，先查明启动/注入来源；无法确定时说明阻塞，不能另写全局文件假装修好 |
| 首次新增且已有项目选择 | 当前调用目录 `.env.local` |
| 首次新增且已有 Plugin Skill 专用选择 | 沿用选择；标准根专用文件为 `~/.config/<plugin>/.env.<skill>` |
| 首次新增且没有既定位置 | 建议个人全局：Plugin 为 `~/.config/<plugin>/.env`，独立 Skill 为 `~/.config/<skill>/.env`，在确认摘要中确认 |
| 目标不可写、被 Git 跟踪、未忽略，或调用者根本不读取 | 报告具体阻塞，不静默换位置、不改索引或忽略规则 |

全局读取仍遵守调用者的启用条件。Plugin 默认自动读取；独立 Skill 不因使用 secret-book 就绕过其全局读取 flag。首次新增默认不预建 Skill 子目录。修复存在的子目录文件则必须写回那里。

`configure` 当前处理普通单行 dotenv 配置。结构化身份组、宿主的只读回退、JSON/YAML 配置或持久化注入脚本需要业务方专用写入入口，不以通用 dotenv 写入替代。写入器支持 macOS/Linux 和原生 Windows；权限与实际验证范围见 README。

## 预览、确认、写入与验证

以下命令由 Agent 操作，路径换成实际安装目录、业务声明和无值报告；不把值放入参数：

```bash
uv run --project "${SKILL_DIR}" "${SKILL_DIR}/scripts/secret_book.py" configure \
  --requirements "<业务产物>/references/credentials.json" \
  --inspection "<任务目录>/config-inspection.json" --agent codex \
  --id <记录ID> --key <需新增或修复的业务字段> --use-global-config
```

上述示例还须追加 `--workflow <task.id> --workflow-agent <实际宿主>`，任务来自 [角色入口](roles.md#记录任务与执行)。`--agent` 与任务宿主须相同。

`--key`、`--id` 可重复。表中 key 不同可用 `--map TARGET=SOURCE` 明确对应。`--scope project|global` 只选择**新增**字段的位置；新建 Plugin 的 Skill 专用文件加 `--skill-only`。当前 Skill 来自报告，不根据 `node/python` 命令名识别。`--agent-config-dir`、`--agent-workspace` 和 `--agent-id` 将宿主上下文传给本次规则检查。

1. CLI 读取并核对本机报告，再查询所选表的实际 key。退出码 `3`、`status: confirmation_required` 表示等待确认，尚未写入业务文件。向用户展示 `review` 中的令牌配置/表/身份、记录名称与 ID、服务/账号、表中 `source_key` → 业务 `key`、缺项和默认值使用情况，以及每个目标文件、替换项和当前来源。值隐藏。需要修复的字段必须明确传 `--key`，不会为方便覆盖其他有效字段。
2. 声明的关联组也要核对。未选的同组字段与记录不同则返回 `related_fields_differ`；先核对服务与账号，再把确实需修复的字段加入 `--key` 重新预览。没有用户确认不能把关联 URL 一并覆盖。声明中的默认值也会参与比较。
3. 用户确认完整摘要后，在**相同命令**后追加 `--confirm <confirmation_token>`。CLI 重新核对声明、报告、本机文件/环境、表/身份、记录、值、映射和规则检查摘要。变化则旧确认失效。跨轮用 `configure-status --requirements <声明>` 恢复 pending 的参数和摘要；本任务 token 取自 `workflow status`，不要换成底层业务配置记录的 token。token 存在不代表用户已经同意。
4. CLI 将值直接从脚本内存写入已确认文件；macOS/Linux 权限为 `0600`，Windows 在写值前设置并校验仅当前用户与 SYSTEM 可访问的 DACL，无法设置则停止。保留未选字段和注释，替换选定字段的重复赋值。不改已有项目目录权限，不生成明文备份。每个文件原子替换并回读；多个文件不构成一个事务。`write_incomplete` 会列已验证文件及待回读文件，先逐个核对，不能声称全部成功或直接重放。
5. `written` 只证明文件字段回读成功。Agent 随即直接运行调用者的配置检查，分别报告：写到哪里、每个字段实际由哪里读取、本机检查结果及线上鉴权是否验证。需要鉴权时使用业务方有据可查的只读入口；不要为了验证配置提交生成任务。
6. 告知用户：“已写入〈完整路径〉。如需只在项目使用，可以让我检查当前项目 `.env.local` 的忽略规则和覆盖关系，再确认迁移。”修复本来就在项目中时报告已是项目配置，不再推荐迁移一次。

本机选择与确认记录在 `~/.config/secret-book/consumer-configurations.json`，权限 `0600`；只含元数据、摘要和校验值，不含凭证值。它用于跨轮确认和后续取用时核对，不是业务运行配置。未经发布的旧 `connections.json` 不再控制运行，也不自动迁移；`run --requirements` 会拒绝执行并提示配置写入入口。

## 后续使用与轮换

业务程序正常直接读取自己的配置文件。没有安装 secret-book、飞书暂时不可达或表中已轮换密钥，都不会改变已保存的本机值。表中变更**不自动同步**；用户要求重新取用或再次需要修复时，重新检查本机来源和手动修改，再预览、确认、写入。

来源表或默认配置改变也不主动修改业务文件。修复后不要继续拿旧报告或旧进程判断；MCP/服务已加载旧配置时按其机制重启或重新加载，并检查实际来源。原任务的恢复条件继续由业务方决定，例如 AIhub 会核对原服务与密钥指纹，换 Key 不授权重发原任务。

## 临时取用

只有短期令牌、仅本轮、不允许落盘或目标不支持保存时才使用显式 `run --id ... -- <命令>`；用户已确认的旧临时绑定仍可 `run --auto`，`--bind` 只在用户要求记住时使用。没有业务声明时先确认真实配置项与目标格式；能保存时优先建议业务专用保存入口，不能为了少实现一个写入器而每次查表。禁止用 `run` 拼接任意写文件命令绕过预览、来源检查和 Git 保护。

## 业务声明与报告格式

声明 `schema_version: 1`；`consumer` 为 `{"kind":"plugin","name":"example","skills":["example-a"]}` 或 `{"kind":"skill","name":"example"}`。`keys` 的每项声明 `required`、`sensitive`、`description`，非敏感项可以有 `default`。`groups` 是有关联的字段数组，例如 `[["EXAMPLE_KEY","EXAMPLE_URL"]]`。声明内不保存用户表、记录、账号和值。

报告 schema 为 `secret-book.config-inspection/v1`：`consumer` 仅含 kind/name，`skill` 必须显式提供，取真实 Skill 名，或在下述 Plugin 共享模式中取 null；`cwd` 是规范绝对调用目录，`global_enabled` 表示本次是否启用全局读取。`layers` 按读取顺序列 `{path, revision}`；文件存在时 revision 为原始字节 SHA-256，缺文件为 null，读取错误须另标 `error`。`environment` 给每个声明字段的非空进程值 SHA-256（无值为 null）；`fields` 列 `{source,present,problem?}`，source 为完整文件路径、`environment`、`built-in default` 或 `missing`。报告可以有脱敏 `problems`。这些校验值仅用于拒绝过期报告，不能代替鉴权。

自 2.5.1 起，Plugin 没有真实业务调用方时，报告须显式保留 `skill: null`。此时只接受工作文件夹的 `.env.local`、`.env`，以及启用全局时的 Plugin 根 `.env.local`、`.env`；不读取任意 Skill 专属文件或普通 Skill 回退。不接受省略 skill 字段，也不能为满足接口借用一个 Skill 名称。独立 Skill 仍须提供真实名称。共享模式禁止 `--skill-only`，新增沿用 Plugin 共享文件或明确的项目范围，已有错误仍写回原来源；确认及公开恢复摘要保留 null。

报告必须由调用者自己的加载器生成，不能让用户猜路径或让 Agent 手写一个“期望来源”。调用者使用其他格式或读取顺序时，应先提供相应写入器及来源验证，不伪造这份报告。
